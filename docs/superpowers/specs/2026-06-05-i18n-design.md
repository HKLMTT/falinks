# i18n 中英双语设计

日期:2026-06-05
状态:已与用户对齐(范围/命令形式/持久化/切换语义四问 + 方案 A 均已确认)

## 需求

falinks 支持中英两种语言:默认自动跟随系统语言,可用命令手动切换。

用户决策记录:
- **范围**:全部三类文案——① UI 文案(控制台/向导/CLI/错误);② 注入给 AI 员工的文案(协作规则、bootstrap 派生、「【来自 X】」消息格式、预设团队角色描述);③ 牛马 slogan(英文版重写成对应语气的英文梗,不直译)。
- **切换命令**:控制台 `/lang` + CLI `falinks lang`,都**弹选择器**(↑↓ 选,Enter 确认),不带参数。
- **持久化**:全局用户级 `~/.falinks/settings.json`。
- **运行中切换**:自然生效——UI 立即换;后续注入的消息格式用新语言;已在岗员工的协作规则不重注入(AI 双语都懂,不打断干活)。

## 设计

### 1. i18n 核心模块(src/i18n/)

- **`zh.ts`**:中文基准词典,导出 `export const zh = { ... }`。纯文本=字符串;带变量=箭头函数(普通函数插值,无模板魔法)。包含全部 ~80 条文案 + `taglines` 数组。
- **`en.ts`**:`export const en: typeof zh = { ... }`。**类型钉死对齐**:漏 key 或函数签名不符 → tsc 编译失败。翻译完整性由编译器兜底。
- **`index.ts`**:
  - `type Locale = 'zh' | 'en'`,模块级 `current: Locale`,**初始值 'zh'**(基准语言,保证测试确定性——测试不读用户 settings、不受 CI 的 LANG 影响)。
  - `t(): typeof zh` 按 current 返回词典;`getLocale()` / `setLocale(l: Locale)`。
  - `detectLocale(env): Locale`:`LC_ALL`/`LC_MESSAGES`/`LANG` 依序取首个非空,以 `zh` 开头 → 'zh',否则 'en';全空回退 'zh'。
  - `initLocale()`:读 settings(`locale: 'zh'|'en'|'auto'`,缺省 'auto'),'auto' → detectLocale(process.env)。**只在进程入口调用**(cli.ts main、console/main.tsx),库代码/测试不自动初始化。

### 2. 设置持久化(src/settings.ts)

`~/.falinks/settings.json`,形如 `{ "locale": "auto" }`。`loadSettings(root?)` / `saveSettings(s, root?)`,root 注入便于测试,损坏/缺失回退默认值(与 store/runtime 同模式)。预留其他设置扩展。

### 3. 文案替换(全量盘点)

| 位置 | 内容 |
|---|---|
| `src/console/app.tsx` | TAGLINES、/help 文本、全部 status 消息、向导文案、答题/退出确认、底部提示 |
| `src/console/commands.ts` | 命令 usage/hint |
| `src/console/parse.ts` | 用法错误信息 |
| `src/cli.ts` | 帮助、doctor、init/找不到配置等全部 console 输出 |
| `src/setup/app.tsx` | 更新提示、团队选单、自定义团队向导 |
| `src/update.ts` | 更新相关文案(如有) |
| `src/index.ts` | HOUSE_RULES(协作规则)、`你的身份:…`、启动等待/就绪/下线日志、防双开/竞态错误 |
| `src/orchestrator.ts` | 「【来自 X】…(回复请调用 sendmsg…)」注入格式 |
| `src/bus/server.ts` | 「对"…",老板选择:…」、MCP 工具 description |
| `src/templates.ts` | 预设团队名与角色描述、`bootstrapForRole` 派生句 |
| `src/core/guards.ts` 等 console.warn | 一并入词典(便宜) |

不翻:README/CHANGELOG(文档另议)、用户自存模板里的角色文字(用户内容)、配置文件内容。

### 4. [图片N] 附件占位符

英文 locale 下占位符为 `[Image N]`。**识别端必须双语兼容**(与生成端 locale 解耦,防切语言后旧占位符失效):
- `clipboard.ts` 的 `expandImageTokens` 正则改为 `\[(?:图片|Image)(\d+)\]`;
- `app.tsx` 退格整体删除的正则同样双语。

### 5. 运行中切换与跨进程传播

控制台和 up 可能是**两个进程**(窗口回退模式)。locale 是进程内状态,切换必须传播:
- 总线新增 `POST /admin/lang {locale}`(zh/en/auto):up 进程 `setLocale`(auto 先 detect)并 `saveSettings`,返回生效的 locale。
- 控制台 `/lang` 选择器确认后:POST /admin/lang → 用返回值本进程 `setLocale` → bump 一个 state 触发整树重渲染。单窗口模式(同进程)同样走这条路,天然一致。
- `falinks lang`(CLI,无办公室运行也可用):Ink 选择器(复用 setup 的选单交互),写 settings;若 resolveBus 找到活实例,顺带 POST /admin/lang 让运行中的也切。
- 选择器选项:`跟随系统(auto)` / `中文` / `English`,当前值高亮。

### 6. 注入文案的时效语义

- 「【来自 X】」格式、ask 选项消息:投递时实时取 `t()` → 切换后新消息即新语言。
- HOUSE_RULES/bootstrap:启动或 `/clear` 重注入时取 `t()` → 已在岗员工不补发。
- `bootstraps` Map 缓存的是生成时语言的完整 bootstrap,`/clear` 重注入沿用缓存(可接受:身份连续性比语言一致性重要)。

## 测试

- i18n 模块:detectLocale 各 env 组合;setLocale/t() 切换;en 与 zh key 对齐(编译期已保证,补一条运行时 key 集合相等测试防 `as any` 逃逸)。
- settings:读写/损坏回退/缺省 auto。
- clipboard/退格:`[图片1]` 与 `[Image 1]` 都能展开/整删。
- parse/commands:`/lang` 进入选择器动作。
- bus:`POST /admin/lang` 切换并返回生效 locale。
- 现有断言中文文案的测试:默认 locale='zh' 不初始化即中文,应全部不动;个别改从 `zh.ts` 引用常量以解耦。

## 接受的限制

- 切换语言不重注入在岗员工的协作规则(用户已确认)。
- `/clear` 后 bootstrap 用生成时语言。
- README 暂不双语。
