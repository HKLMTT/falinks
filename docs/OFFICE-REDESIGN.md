# OFFICE-REDESIGN — 像素办公室「细节打磨」设计方案

> 出品:ux(设计走查) · 实现:frontend · 风格基准:`docs/SPRITE-SPEC.md`
> 现状产物:`demo-board.png`(主视图)/`demo-detail.png`(详情) · 调色板事实源:`src/office/web/assets/sprites.json`
> 红线不变:暖色 cozy 俯视;改色一律走 sprites.json;状态两级冗余(脚下 tile 为主 + 头顶浮标为辅);静帧可分。

本方案**只出设计 + 验收标准,不写代码**。优先级 **P0 先做**(空旷布局 + 状态可读性,体感提升最大),P1/P2 列后续。所有引用的常量/选择器都对齐现有代码,frontend 可直接照做。

## 0. 现状量化(读图 + 读码结论)

| 现象 | 根因(代码定位) |
|---|---|
| 房间缩在左中、右侧大片黑、上下黑边、大屏更空 | `#stage` 固定像素尺寸(`SCALE=4` 烘进几何),`#stage-wrap` 仅居中不缩放 → 房间宽 ≈896px 漂在大画布里 |

| offline 与「休息」撞车 | offline 在工位压暗;boss/intern 在沙发 → 两种「不在干活」缺少明确区分语义 |
| 无图例、颜色靠猜 | 屏上无任何 legend;未选中态右栏只有一句 hint,信息密度为 0 |

## 状态视觉编码规范(规范节 · 三处一致的单一事实源)

> 这一节是 frontend 实现状态视觉的**唯一事实源**。屏上三处——**头顶浮标 / 脚下地台 / 右栏图例**——必须用同一套状态语言:每个状态 = **固定形状 + 固定主色 + 固定地台表现**,图例小样与场内真实渲染**逐像素同款**。
> 落地约束:这套定义集中存放在 `sprites.json.status[*]`(色 + tileGlow + floater 形状 key),CSS 的 `.tile.<state>` / `.floater.<state>` / `.legend .<state>` 与 i18n `st.<state>` **全部读同一套 key**,不得在某一处私自换色/换形(防跑偏)。

| 状态 | 形状(浮标字形) | 主色(sprites.json key) | 脚下地台(tile) | 浮标样式(底框) | 图例小样 | 语义 |
|---|---|---|---|---|---|---|
| **idle** | 无(留白即信号) | `idle` `#8893A8` 冷灰蓝 | 不发光,本色砖 | 无浮标 | 灰蓝色块 + 「(无标)」 | 在岗待命、肩慢呼吸 |
| **busy** | ●(实心圆,CSS 形状无字) | `busy` `#5FB84A` 绿 | 绿色脉冲发光(1.1s) | 圆形,绿底深描边 | 绿 ● | 正在工作:屏滚动、敲键 |
| **waiting** | …(三点) | `waiting` `#F2A33C` 琥珀(hue≈34°) | 琥珀呼吸(1.5s)+ 常驻深环 `#8A4A12` | **圆角矩形**,琥珀底深描边 | 琥珀 … | 正常等待(有待答问题/挂起) |
| **stuck** ⭐ | !(单字) | `stuck` `#D2483A` 警示红(hue≈6°) | **红快脉冲(0.7s)**+ 深环 | **▲三角**,红底深描边 | 红 ! | 卡住/无响应,需介入 |
| **done** | ✓(对勾) | `done` `#2FA4C8` 青 | 青光闪 1 次 → 余辉 → 淡出(共 3s) | 圆角矩形,青底深描边,pop 入场 | 青 ✓ | 刚完成(瞬态,可感知) |
| **offline** | ✕(叉,空心) | `offline` `#5A5A60` 暗灰 | 熄灭/压暗 | 圆角矩形,灰底空心 | 灰 ✕ | 离线断电:屏黑、小人灰 |

**规范自检(frontend 实现后逐条核对)**
- 形状 6 选互不撞:`无 / ● / … / ! / ✓ / ✕`。
- 主色 6 选色相拉开:灰蓝 / 绿 / 琥珀34° / 红6° / 青 / 灰。
- 去色(灰度)后仅凭**形状**仍可分;去形(只留 tile 主色)相邻态欧氏色距 ≥ 60。
- 浮标底框形状本身也编码:**圆=busy / 圆角矩形=waiting·done·offline / 三角=stuck**(waiting↔stuck 即使同手滑用相近色,靠圆角 vs 三角也能分)。
- 三处同源:改任一状态的色/形,只改 `sprites.json`,CSS/图例/pill 自动跟随,无第二处硬编码。

下文 P0-2 的「6 态表」与「图例」均**实现自本节**,不另立定义。

## P0-1 空间利用 / 布局自适应

### 解法

**A. 舞台 fit-to-viewport(消黑边、铺满、大屏自适应)**
- 保留内部 `SCALE=4`(像素清晰度不动),在 `#stage` 上叠一层 `transform: scale(k)`,`k = min(wrapW/stageW, wrapH/stageH)`,`transform-origin: center center`。
- `k` 夹在 `[1, 2]`,并**吸附到 0.25 的整数倍**(`Math.floor(k*4)/4`)→ 防止非整数缩放糊像素。
- `fitStage()` 在每次 `layoutRoom()` 之后 + `window.resize`(debounce 100ms)各调一次。
- `#stage-wrap` 保持居中,`padding` 从 24px 收到 16px。

**B. 工位均衡分行(消灭「lead 单独一行」)**
- 用「尽量方阵」替代固定 5 列:`rows = Math.ceil(count / COLS_MAX)`(`COLS_MAX=5`),`perRow = Math.ceil(count / rows)`。
  - 6 人 → 3×2(不再 5+1);7 人 → 4+3;8 人 → 4×4;≤5 人 → 单行。
- 工位块 + 公共带整体在房间内**垂直居中**(当前是顶对齐留底空):房间高按内容算,desk 块上方留白 = 下方公共带的对称感(上 ≥ `WALL_H` 落地、下 ≥ 一个 `CELL`)。

**C. 空白填充——cozy 功能区(全部复用现有 atlas,无需新美术)**
未用到的现成 sprite:`counter / bench_sm / bench_lg / sofa_blue / sofa_green / sofa_gray / vending2 / plant_tall / elevator`。按区布置:
- **茶水间角**(房间右下):`counter` + `vending2` + 一株 `plant_tall`,贴右墙。
- **会议/休息角**(房间左下或中下):`sofa_red` + `sofa_blue` 成 L,中间垫一块**圆形地毯**(CSS 椭圆,用 SPEC 地毯色 `#B8503C` 暖红 / 边 `#EAD9B0`),猫狗趴地毯上。
- **绿植锚点**:房间四角各放 1 株 `plant_tall`,把空棋盘格「收边」。
- 公共带改为**按房间宽等距铺开**(`buildDecor` 里用 `W` 均分而非写死 `W*0.30/0.42`),人少时也不空。
- 地毯/家具只落在**墙带 + 工位下方公共带**,绝不压工位行与头顶浮标区(SPEC 红线 5)。

**D. 未选中态右栏给默认内容**(详见 P0-2 图例 + 概览)——不留空白。

### 验收标准(量化)
- [ ] 任意窗口尺寸(含 ≥1920 宽)下,`#stage` 占满 `#stage-wrap` 可用区:**左右剩余留白各 ≤ wrap 宽的 8%**,上下各 ≤ 8%。
- [ ] 缩放系数 `k` 为 0.25 的倍数;放大后地砖边缘无半像素模糊(目视棋盘格线清晰)。
- [ ] 6 人 roster 渲染为 **3×2**,无单人尾行;lead 不再孤悬。
- [ ] 工位块在房间内垂直居中:工位行上方留白与公共带下方留白之差 ≤ 1 个 `CELL`。
- [ ] 房间内**无任何 ≥ 3×3 `CELL` 的连续空棋盘格**(被家具/地毯/绿植/动物填充或收边)。
- [ ] 新增装饰全部来自现有 atlas,sprites.json 无新增图片资源。
- [ ] resize 窗口时房间平滑重新 fit,无错位/溢出滚动条。

## P0-2 状态可读性(图例 + 6 态双编码)

> 核心:把当前 5 态扩成 **6 个可视态**(把 `stuck/unresponsive` 从 waiting 里**拆出来**),每态 **色 + 形 双编码**,静帧两两可分(SPEC 红线 3)。

### A. 常驻状态图例(屏上,不靠猜)
放进**右栏未选中态**(同时解决 P0-1 D「右栏别空着」):
```
团队概览
─────────────
在岗 N · 忙 N · 等待 N · 卡住 N · 离线 N        ← 实时统计(来自 roster)

状态图例
● 绿   忙碌    □ 灰蓝(无标)  空闲
… 琥珀 等待    ! 红(三角)    卡住
✓ 青   完成    ✕ 灰          离线
```
- 每条 = 浮标小样(同屏内真实样式)+ 颜色块 + 文案,色弱也能靠形认。
- 选中某工位后,右栏切换为详情;取消选中回到概览+图例。

### B. 6 态视觉编码

**实现见上方「状态视觉编码规范」节**(每态的形状/主色/地台/浮标/图例/语义,单一事实源)。本节只补**微动 / 屏幕**等氛围细节(不单独承担状态语义,SPEC 红线):
- busy:屏滚动、双手 ±1px 交替敲。
- waiting:屏顶琥珀提示条、身体静止。
- stuck:屏顶红条、小人 ±1px 微抖(警示)。
- done:屏闪青、头轻抬一下。
- offline:屏全黑、小人灰度 .6 / 透明 .45。

### C. stuck 拆分(改 `visualState`)
- office.js:102-103 现状 `stuck/unresponsive → 'waiting'`,**改为返回 `'stuck'`**;`questionFroms`(有待答问题)仍 → `'waiting'`(那是正常等待,不是卡住)。
- 新增态需要在三处补齐:`sprites.json.status.stuck` + `sprites.json.palette.stuck` + CSS `.tile.stuck/.floater.stuck/.status-pill.stuck` + i18n `st.stuck`(zh「卡住」/ en「Stuck」)。
- 工位屏幕列:`workstation.states.stuck` **先复用 `waiting` 的列**(列 2),不强求新美术(新画一列归 P1)。

### D. done 可感知(瞬态 → 可见)
- `DONE_MS` 1500 → **3000ms**;done 期间 tile 保留**柔和青色余辉环**(闪 1 次后 0.5s 渐隐为常亮 1.5s 再淡出)。
- ✓ 浮标**带 pop 缩放**(scale 1.3→1.0)入场,停留整个 done 窗口。
- 详情面板加一行「上次完成 hh:mm」(从 `doneUntil`/log 取),即使错过动画也能查到 → 满足「可感知的刚完成」。

### E. offline 不撞「休息」
- offline(工位,`status==='dead'`):屏**全黑** + 小人**灰度 .6 / 透明 .45**(已有)+ 浮标 **✕ 灰空心** + 名字降到 `#8a7a5e` → 「断电下班」感。
- 休息成员(boss/intern 在沙发,`virtual`):**不套 offline 样式**,给一个 **☕「离座」小角标**(暖色,非灰),与「离线」明确分语义。
- 自检:offline = 灰 + 屏黑 + 在工位;休息 = 暖角标 + 在沙发。两者无视觉重叠。

### 验收标准(量化)
- [ ] 屏上常驻图例,6 态(含 idle 无标)全列出,浮标小样与场内真实一致。
- [ ] 同屏并列 6 态截图:任两态**裁掉颜色(灰度)后仍可凭形状区分**;裁掉形状(只留 tile 色)相邻态欧氏色距 ≥ 60。
- [ ] waiting 与 stuck:tile 色相差 ≥ 25°(琥珀 ~34° vs 红 ~6°),浮标形状不同(圆角矩形 … vs 三角 !)。
- [ ] `#D2483A` 仅用于 stuck 的**小面积 tile/浮标**(非整屋大色块),不破暖 cozy(SPEC 红线 1)。
- [ ] done 触发后**≥3s 内**肉眼可见(✓ + 青余辉);详情面板可查「上次完成」时间。
- [ ] offline 与沙发休息成员视觉不混:offline 屏黑+灰,休息成员暖角标+不灰。
- [ ] 概览统计数字与 `/office/state` roster 实时一致。

## P1-1 美术精致度(后续)

- **状态光收进工位**:busy 绿椭圆现在超出桌沿像「绿水/UFO」。tile 椭圆宽从 `34px` 收到 ≤ 桌宽 `28px`,纵向压扁(贴脚下而非整片地),外发光 spread 减半 → 「灯效」而非「水洼」。
- **人物辨识**:5 人现在仅发色微差 + 全靠白标签。在不破骨架前提下,加大**发色/衫色**对比档(深棕/赭红/亚麻/墨绿/灰蓝 5 档分明),lead 保留眼镜+皇冠。
- **标签可读**:名字压浅地砖对比低 → 名字加**深色半透底衬**(`rgba(0,0,0,.45)` 圆角药丸)或加粗描边,而非纯文字阴影。
- **lead 语义去混**:橙皇冠(角色)与状态浮标(状态)同处头顶 → 皇冠下移贴发际、缩小,浮标在更上方,二者纵向错开 ≥ 4px。
- 验收:busy 光不超桌沿;5 人灰度图仍可凭发型/衫色区分;名字在浅砖上对比度 ≥ 4.5:1。

## 繁忙强度分档(busy 态内部子维度 · 并行需求)

> 需求:用员工 inbox 队列长度表现繁忙程度,越长越忙,超阈值"暴躁地工作"。数据:`/office/state` 的 `roster[].queue:number`(backend 提供)。
> **铁律(不可破)**:强度是 **busy 态内部的强度子维度**,**绝不动 6 态视觉语言**——busy 永远 = 绿 `●` 圆浮标 + 绿地台;强度**只改"动得多凶"**(动画速度/抖动幅度),**不换状态色、不换浮标形、不加会和其它态混淆的色**。只有 `visualState==='busy'` 才有强度;其它态忽略 `queue`。`queue` 缺省/undefined → 视为 L0。

### 档位与阈值(默认,可量化)

| 档 | queue | 语义 | 触发类(加在 `.station`) |
|---|---|---|---|
| **L0** | 0(或无) | 普通忙 | `b0`(= 现有 busy 基线) |
| **L1** | 1–2 | 较忙 | `b1` |
| **L2** | 3–4 | 很忙 | `b2` |
| **L3** | ≥5 | 暴躁/抓狂 | `b3` |

- 档位由 `queue` 算出后**只加在 busy 工位**;切出 busy 立即清除 `b0..b3`。
- **防抖/迟滞**:`queue` 在阈值附近抖动易闪档 → 升档立即生效,**降档延迟 1s**(或 ±1 迟滞),避免抽搐式跳档。

### 各档视觉(在现有 busy 动画上递进 · 优先纯 CSS,无需新美术)

现有 busy 基线 = 人物 `rest⇄type` 帧 4fps 切换(office.js `tickFrame`)+ 地台 `glow-busy` 1.1s 脉冲。强度在此之上**叠加**两个 CSS 杠杆:**① `.person` 整体微抖(transform)② 地台脉冲提速**。打字帧率可选提速(见下)。

| 档 | 地台脉冲周期 | 人物微抖(transform,整数像素 step) | 打字帧(可选) | 烦躁强调 |
|---|---|---|---|---|
| L0 | 1.1s(现状) | 无 | 4fps | — |
| L1 | 0.9s | translateX ±1px,~2Hz,轻微 | 4fps | — |
| L2 | 0.7s | translateX/Y ±1px 交替摇,~3Hz | 可选 ~6fps | — |
| L3 | 0.5s | translate ±2px 急抖,~5Hz | 可选 ~8fps | 每 ~2.5s 一次更大"抽动"jolt(±3px 单帧,模拟拍桌/抓头)+ **可选烦躁符** |

**实现要点(防跑偏)**
- 微抖只用 `transform: translate()`(GPU,不重排);**用整数 px + `steps()`**,别用平滑插值,避免像素糊(像素风动起来要"跳"不要"飘")。**不用 rotate**(像素旋转必糊);L3 要更凶就加大 translate 幅度/频率,不靠转。
- 抖 `.person` 这一层即可,**别抖 `.ws` 桌子/`.tile` 地台/`.floater` 浮标**(桌子地台抖会散架,浮标抖会被误读成状态变化)。
- **打字提速可选**:全局 `tickFrame` 是 250ms 定时,不必动;若要 L2/L3 敲得更快,frontend 可让 busy 工位按档跳帧(L3 每 tick 都翻,L0 隔 tick)或单开 per-station 计时。**非必须**,光靠抖动+脉冲提速已能分档。
- **烦躁符(L3 可选,非必须)**:若加,**严格约束**——置于**头侧**(非头顶浮标槽,绝不占 `●` 位)、≤5px、暖/中性色(`warmGlow#F2C879` 填 + `woodLo#7A4F2A`/`base#5C3A20` 描边),**禁用任何状态色**(绿/琥珀/红/青/灰),周期闪现非常驻。形如小"#"汗滴/急促线,纯 CSS 或复用现有像素;**要新帧则在此标注交美术,默认不做**。
- **prefers-reduced-motion**:开启时全档**降到 L1 上限**(去抖动/去 jolt,仅保留脉冲轻微提速),无障碍兜底。

### 验收标准(量化)

- 每次轮询比对:某成员出现 `m.ts > 上次已展示ts` 且 `from===其名` 且**在屏** → 其头顶弹气泡(沿用 `diffBubbles` 逻辑)。
- **扩展 boss**:当前 `stations.has(from)` 过滤会漏掉 boss(走 renderBoss)。改为通用"在屏成员→头顶锚点"解析:工位成员锚到 station,boss 锚到 boss 区头顶。其余非在屏(未渲染虚拟)不弹。
- 只弹 `from`(说话人),不给 `to`。

### 内容 / 截断 / 节流
- 正文截断:**≤ 48 字**(超出 `…`),且 `max-width ≤ 1.6× 桌宽`、**最多 2 行**、行末省略号(现 58 字放宽到 48 更稳)。
- **节流(每人独立)**:同一人新气泡替换旧的,但**每个气泡最小可见 1.5s**;1.5s 内连到的多条**只保留最新一条**(丢弃中间,不排长队、不糊屏);跨人不互相节流(各弹各的)。
- 同一人同屏**至多 1 个气泡**。

### 时长 / 动画(像素风)
- 出现:`pop` 120–180ms(scale 0.9→1 + 淡入,`steps()` 像素感,不平滑拉伸)。
- 停留:`dwell = clamp(2500 + 35ms×字数, 2500, 6000)`(长句多停,封顶 6s)。
- 淡出:200–250ms 淡出 + 轻微上移 ≤2px。
- **reduced-motion**:去 pop/位移,仅瞬显 + 淡入淡出。

### 位置 / 层级(与状态系统解耦 · 关键)
- 锚点:**station 盒**(不锚 `.person`)→ 繁忙度抖动(±1/±2px)时气泡**不跟着抖**(气泡是"说话"非"状态",不能被强度晃)。boss 同理锚 boss 区。

### 边界
- **不溢出舞台**:气泡水平居中,但靠近房间左右边时**整体平移**回舞台内(留 ≥4px 边距),尾巴相应偏移仍指向说话人。

### 样式(暖 cozy 像素)
- 沿用现 `.bubble`:暖白 `#fffdf5` 底 + 深暖字 `#2a2014` + 木色描边 `base #5C3A20` + 向下尾巴;**1–2px 硬描边**强化像素游戏感。

## idle 打瞌睡(idle 态内部随机休眠子动画 · 并行)

> boss 需求:空闲员工随机打瞌睡。与"繁忙强度"对称——这是 **idle 态内部的随机休眠子维度**。
> **铁律(同 busy 强度)**:不破 6 态语言——idle 仍 = 无地台发光 / 无状态浮标;打盹只是 idle 内的随机微动 + "Zzz",**不换状态色/不加状态浮标**。仅 `visualState==='idle'` 可能打盹;**boss 不参与**(坐镇、独立分支无状态)。
> 现实约束:people sprite 只有 `rest`/`type` 两帧、**无睡眠帧**,且头无法单独抽离 → "点头"用 `.person` **整体小幅 bob**(CSS transform)模拟,无需新美术。

### 触发 / 随机模型(每人独立错峰)
- 每个 idle 员工独立循环:**清醒 `8–20s`(随机)→ 打盹 `3–6s`(随机)→ 醒 → 循环**。
- **错峰**:每人随机 `相位/时长/初始延迟` 不同 → 同屏多个 idle **不齐刷**(绝不全员同步点头)。
- 实现优选**纯 CSS**:每 station 注入随机 `animation-duration`(= 清醒+打盹,~`11–26s`)+ 随机 `animation-delay`;keyframes 里前 ~70% 静止、后段才点头+Zzz。免 JS 定时器(浏览器端可用 `Math.random` 逐 station 取值)。
- 离开 idle(变 busy/waiting/stuck/done/offline)→ **秒停**(清除点头 + Zzz),不破状态切换。

### 视觉
- **点头**:`.person` 整体 `translateY 0→+2px→0`,周期 ~`1.0–1.4s`,`steps()` 整数像素,**不 rotate**(防糊);仅在"打盹"段重复,幅度 ≤2px。
- **Zzz**:头顶冒 "z / Zzz" **飘升淡出**(上移 ~6–10px、~1.5–2s 淡出,打盹段内冒 2–3 次)。像素字形,**中性暖色**(如奶白 `#E8DCC0` + 深描边),**禁用任何状态色**(绿/琥珀/红/青/灰),与 6 态浮标 ●…!✓✕ 不混。
- 可选:打盹时屏幕再压暗一点点(idle 屏本就暗)表"休眠"。

### 解耦(参考气泡/强度做法,防打架)
- Zzz 落在**头顶浮标带**(idle 本无状态浮标 → 位置不冲突);`z-index` **低于说话气泡**。
- **与说话气泡冲突规则**:该员工若正显示气泡(= 它在"说话"→ 即醒着)→ **气泡优先**:气泡可见期间**挂起打盹**(隐 Zzz、停点头),气泡结束后恢复随机循环。
- 点头作用在 `.person`;Zzz 作用在独立 Zzz 元素 —— 各自独立,互不拖拽(同气泡"不锚抖动层"思路)。

### 节流 / 边界
- 同屏多 idle 各自错峰、不齐刷(随机相位保证)。
- **reduced-motion**:去点头动效;Zzz **静态单字或不显**(不做飘升)。

### 验收(量化)
- [ ] 仅 `idle` 可能打盹;**boss 从不打盹**;切到任何非 idle 态**立即停**(点头+Zzz 秒清)。
- [ ] 每人随机错峰:同屏 ≥2 个 idle 不同时点头(相位/时长随机)。
- [ ] 清醒 `8–20s` / 打盹 `3–6s` 区间可测;点头 ≤2px、整数、`steps()`、无 rotate。
- [ ] Zzz 飘升淡出、在浮标带、**中性暖色非状态色**、低于气泡 z;不与 ●…!✓✕ 混。
- [ ] 正显示说话气泡时挂起打盹(气泡优先),气泡结束恢复。
- [ ] reduced-motion 下无点头、Zzz 静态或不显。
- [ ] 不破 6 态:打盹中该员工仍读作 idle(无地台、无状态浮标)。

## 动画增强 ②:猫狗自由活动 + 原地动作

> 现状:猫狗在休息区只偶尔原地微动。要在**一片区域内自由走动 + 原地小动作**。基础:cat(16×13)/corgi(24×11)各 **1 帧**。

### 活动区(边界规则)
- 定一个**底左自由活动 bbox**(在公共带、休息区一带):默认 `{ left: PAD, top: L.commonsTop + 8, right: round(roomW*0.38), bottom: cBot - 4 }`。
- **硬边界(逐帧 clamp)**:宠物自身 bbox **恒落在活动区内**,且 **∩ 沙发 bbox = ∅**(不爬沙发)、**不进工位行**(`top ≥ commonsTop` 已保证)、不压 boss 区、不越房间墙(距边 ≥4px)。`right=0.38W`(≈348)不触中轴/茶水间。
- cat 与 corgi 目标点错峰随机,**互不重叠**(可选保持 ≥1 个身位)。

### 走动
- **随机游走**:在活动区内随机取目标点 → 平移过去 → 停顿 → 再取新点。速度 ~`8–14px/s`(慢、cozy);每段停顿 `2–6s`;两只独立错峰。
- **朝向**:按水平位移 `dx` 正负**水平翻转 sprite**(`transform: scaleX(±1)`,整数像素无糊),面向行进方向。
- 实现:轻量 JS(每只维护 `当前点/目标点/状态`,用 CSS `transition: left/transform` 或 rAF 推进);移动量用整数 px。位置作用在宠物容器,不与原地动作层互拖(参考气泡/打盹解耦)。

### 走路帧 / 原地动作
- **走路帧(优选,更可信)**:`build-sprites.py` 给 cat/corgi 各加 **2 帧走路循环**(腿前后交替),移动时 ~`4fps` 循环,停下回 rest 帧。
  - **兜底(不加帧)**:单帧 + 移动时轻微 hop/squash(`scaleY` 1→0.94→1,`steps()`)模拟步态。
- **原地动作**(停顿时随机触发,频率 ~每 `5–10s` 一次,~0.6–1s):
  - 纯 CSS 微动(复用现 pet-hop 思路,无新美术):**伸懒腰**(`scaleY` 拉伸/`scaleX` 微扩)、**坐起小 bob**、**甩尾/抖身**(极小幅 translate,`steps()`)。
  - 想要更生动(挠痒/真甩尾)→ 需额外帧,**标注可选新美术,默认 CSS**。
- **reduced-motion**:停止游走(停在当前点)、去原地动作,回静态单帧。

### 验收(量化)
- [ ] 猫狗在活动区内自由游走,**自身 bbox 恒不越界**、不爬沙发、不进工位行/boss 区、不出房间墙(≥4px)。
- [ ] 速度 `8–14px/s`、停顿 `2–6s`、两只错峰;按 `dx` 水平翻转面向行进方向。
- [ ] 走路:2 帧循环(或兜底 hop/squash);停下回 rest;原地动作每 `5–10s` 偶发、克制不喧宾夺主。
- [ ] 帧方案(build-sprites 加 2 帧)或 CSS 方案择一落地;新帧均已标注。
- [ ] reduced-motion 下停走动 + 去动作、回静态。
- [ ] 只动猫狗;工位/状态/强度/气泡/打盹/沙发/书架等不受影响。
