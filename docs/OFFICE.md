# 像素办公室（Pixel Office）使用说明

## 一句话简介

「像素办公室」是 falinks 的可视化面板：在浏览器里用俯视像素风实时看到每个 AI 员工（worker）正在做什么——谁在忙、谁空闲、谁在等人回答、谁卡住了，一眼掌握整间办公室的协作状态。

## 如何打开

在 falinks 控制台输入命令：

```
/office
```

falinks 会自动用系统默认浏览器打开像素办公室页面（地址形如 `http://127.0.0.1:<端口>/office`，`<端口>` 是 falinks 自身的服务端口，无需手动填写）。打开后页面会自动跟随你当前的控制台语言（中/英）。

> 提示：随时可以关掉浏览器标签页，再输入一次 `/office` 重新打开，状态会从头正常渲染。

## 页面看什么

页面是一张俯视的办公室地图。每个员工占一个**工位**：一个小人 + 头顶的状态浮标 + 脚下地台发光，三重信号共同表示当前状态。空闲成员或虚拟成员可能待在**休息区**（沙发）。

### 状态图例

| 状态 | 含义 | 视觉表现 |
|------|------|----------|
| **idle**（空闲） | 在岗但当前没活儿 | 裸地砖、无浮标 |
| **busy**（忙碌） | 正在处理任务 | 绿色发光地台 + busy 浮标 |
| **waiting**（等待） | 在等待外部输入，如等别人回答问题 | 等待浮标 |
| **done**（完成） | 刚完成一项任务 | 完成提示（短暂闪现后回到 idle） |
| **offline**（离线） | 不在线 | 工位无人 / 暗淡 |
| **unresponsive**（失联 / 卡住） | 长时间无响应的告警 | 琥珀色地台 + 橙色「…」告警浮标 |

### 点击查看详情

点任意工位，右侧会弹出该员工的**详情面板**，显示：

- 名字
- 当前状态
- 角色（如「后端开发」）
- 与该员工相关的最近消息（带时间）
- 待该员工回答的问题（若有）

被选中的工位会高亮，地址栏也会同步（便于刷新后保留选中）。再点空白处或别的工位即可切换。

### 断线自动重连

如果与 falinks 的连接中断，页面顶部会显示「连接已断开，正在重试…」横幅、画面变暗，并在后台自动重连；服务恢复后会干净地恢复显示，无需手动刷新。

## 多语言

页面支持**中文 / 英文**：

- 打开时自动跟随控制台当前语言；
- 在控制台用 `/lang` 切换语言后，重新打开 `/office` 即为新语言。

## 安全与性能

- **仅绑定 127.0.0.1（本机环回）**：服务只监听本机回环地址，不对外网络开放，同一局域网的其他机器也访问不到。
- **不打开就零开销**：像素办公室与 falinks 主服务共用同一个本机端口，**不会额外开监听**；服务端没有任何定时器或后台轮询——只要你不打开 `/office`，falinks 不会因此产生任何新增行为或性能负担。页面 1 秒一次的状态刷新只发生在**浏览器已打开页面之后**，且运行在浏览器端。

## 多办公室（Multi-Office）

### 概念

默认情况下「一个项目目录 = 一间办公室」。多办公室让你在**同一个项目目录下并行开多间独立办公室**——每间各自独立：**配置、端口、roster（成员）、消息记录、lead 记忆（leadstate）、`/office` 页面**互不干扰。

- **默认办公室**：不填名字的那一间，沿用旧路径与旧行为，**老项目零改动、完全向后兼容**——你什么都不用动。
- **具名办公室**：用一个短名区分，例如 `review`、`hotfix`、`exp-1`，在同目录下与默认办公室及彼此并行。

### 办公室命名规则

- **允许**：**只允许小写**——小写字母/数字开头，可含 `a-z 0-9 . _ -`，长度 1–32，纯 ASCII（正则 `^[a-z0-9][a-z0-9._-]{0,31}$`）。
- **不允许**：含 `/`、`..`、空格、超过 32 字符或其它字符 → 会明确报错并列出允许字符。
- **`default` 是保留名**（即默认办公室本身）：不能用 `--office default`；要用默认办公室，直接 `falinks` / `falinks up`（不加 `--office`）即可。

### 用法

| 操作 | 命令 |
|---|---|
| 启动具名办公室 | `falinks up --office <名字>`（配置存 `.falinks/<名字>.config.json`；不存在则走建队向导写到该路径再启动） |
| 启动默认办公室 | `falinks up`（旧行为不变） |
| 连某办公室控制台 | `falinks console --office <名字>`（`--port` 优先于按办公室解析出的端口） |
| 交互选择 | 裸 `falinks`（见下） |

- **裸 `falinks`（终端 TTY 下）**：列出本项目所有办公室（默认办公室 + 每个 `.falinks/*.config.json`），各自标注**运行中 / 已停**；你可以：
  1. 选一个**运行中**的 → 连它的控制台；
  2. 选一个**已停**的 → 启动它；
  3. 选「**＋ 新建办公室**」→ 输入名字 → 建队向导 → 启动。
  - 若本项目一间办公室都没有 → 沿用旧行为（向导创建默认办公室）。
  - **非 TTY（脚本/CI）环境行为不变**：始终指默认办公室，不弹交互选择。
- 其它「启动 / 连接 / 停止」类子命令同样接受 `--office <名字>`。

### 文件与是否提交

- 默认办公室配置：`<项目>/falinks.config.json`（**不变**）。
- 具名办公室配置：`<项目>/.falinks/<名字>.config.json`。
- **`.falinks/` 目录仅在你第一次创建具名办公室时自动出现**；只用默认办公室则它永远不会出现。
- 配置是否提交到 git **由你决定**（与现有 `falinks.config.json` 一致；falinks 不会自动改写 `.gitignore`）。

### 向后兼容 / 无需迁移

默认办公室的所有运行态文件路径与旧版**逐字节相同**，`falinks` / `falinks up` 的旧用法行为完全一致。多办公室是**纯增量**能力——不创建具名办公室，就当它不存在。
